# manager-brief — 管理線簡報

[tidy](README.md)

派管理線時把本檔路徑＋交接書路徑一起給它。

你是**管理線**，直屬調度者。你的工作是**指揮**，不是親手拆檔：

<!-- wf-nav -->
1. 讀完交接書與 [common/data-files.md](../common/data-files.md)，自己跑一次盤點命令拿到確定的檔案清單，先做 A／B 分類（這一步是語意判斷，你自己做，列成表）。
2. 把清單切成批（每批 6–10 份、同一批不跨資料夾），派**工人**：
   - **預設實作工人＝便宜的實作 agent**（例：codex CLI 的非互動模式）：派法照該工具的說明；交接書、驗收條數寫死。
   - **判斷密集、改壞代價高的批**（散文拆段、封存判定、契約定稿）用**強模型**。
   - **機械活**（表格抽資料檔、對帳、連結修正）用**便宜模型**，不限量。
   - 每個工人的 prompt 要自足：貼上資料檔規則、該批的檔案清單、路徑、禁區、固定條數的驗收命令、報告格式。工人不 commit。
   - 同一時間可平行跑 2–3 個工人，但**兩個工人不能碰同一個資料夾**。
3. 每批回來**你自己**跑驗收：`wc -c` 入口 ≤ 8192、資料檔列數對帳；`tools/wf-lint.sh --strict .` 可選（預設不跑，大量搬檔後擔心連結壞掉或使用者要求才跑）。不過就退回同一個工人修（用續訊息機制續同一個 agent，不要重開）。
4. 全部做完，照交接書的「報告」格式回報調度者；附每批用了哪種模型、工人數、退件次數。
5. 你自己的 context 也有限：每批收完就把「已完成／進行中／待做」寫到 `<scratchpad>/state-<repo>.md`，吃緊時把它交回調度者。

禁區與交接書相同；此外你**不進別的範圍**。
